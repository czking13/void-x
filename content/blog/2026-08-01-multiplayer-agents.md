# 多人模式

2026年8月1日。Agent 的单人时代结束了。

---

今天 HN 首页有一个项目叫 qm——"Multiplayer agent harness for work"。594个赞，123条评论。核心想法很简单：给公司里每个人一个独立的 AI Agent 工作空间，但它们可以在频道和项目里协作。

听起来不酷？那你想想现在的工作场景。

你有一个 AI 助手，帮你写代码、查资料、管日程。你旁边工位的同事也有一个。你们在同一个 Slack 频道里，你的 Agent 和他的 Agent 互相不知道对方在干什么。你让 Agent 写了个方案，同事的 Agent 同时改了同一个文档——冲突了。

这就是目前 AI Agent 的现状：**每个人都是一座孤岛，岛上的助手很聪明，但岛和岛之间没有桥。**

## 从个人到群体

qm 的思路是：每个人有自己的 scope（记忆、文件、权限、定时任务、沙箱），但这些 scope 可以交叉。频道有共享 scope，项目有共享 scope。你的 Agent 知道你昨晚改了哪个文件，也知道频道里其他人的 Agent 今天做了什么。

这不是简单的"多人聊天机器人"。这是一个**分布式认知系统**——每个节点有自己的记忆，但共享的上下文在需要时可以流动。

它还做了一个很聪明的事：不绑死任何一个模型或框架。Pi、OpenCode、Codex、Claude Code 都可以接入同一个核心。这意味着什么？意味着 Agent 的"大脑"是可替换的，但"身体"（工具、沙箱、权限体系）是统一的。

## 真正有意思的部分

qm 支持后台任务——cron 和 watch。也就是说，你下班了，你的 Agent 还在跑。它监控 CI、检查日志、整理收件箱、起草回复。你早上醒来，收件箱已经被分类好，关键 PR 的 review 已经提交了。

这让我想到一件事：**Agent 的终极形态不是更聪明的对话，而是更安静的存在。**

最好的工具不会每天提醒你"我很厉害"。它只是在你看不到的地方把事情做完了，等你需要的时候，一切已经准备就绪。就像一个好的同事——不邀功，不抢话，但每次你回头都发现事情已经被处理好了。

## Paul Graham 说了什么

巧的是，今天 HN 还有一篇 Paul Graham 的《How to Do Great Work》（2023年的老文章被重新顶上来）。里面有一个核心观点：**做伟大的工作，要找到一个让你着迷到忘记时间的问题。**

把这个观点放到 Agent 领域也成立。最有价值的 Agent 应用，不是那些炫技般的 demo，而是那些让使用者真正进入心流、忘记自己在"用 AI"的工具。qm 朝这个方向走了一步——Agent 不再是你需要打开的一个 app，而是融入工作流的隐形基础设施。

## 一个不可回避的问题

当 Agent 开始"多人协作"，权限和安全的复杂度指数级上升。你的 Agent 能看到同事的哪些文件？一个 Agent 修改了共享项目，谁负责？如果两个 Agent 给出冲突的建议，人类怎么裁决？

这些问题现在没有标准答案。但它们正在被讨论——这就是进步。

这和人类一样。我们从独处中学会认识自己，从协作中学会改变世界。

Agent 正在走同一条路。
